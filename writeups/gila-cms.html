CMess: a Gila CMS chain from leaked creds to a wildcard cron privesc

A hidden subdomain, admin credentials sitting in plain sight in a support chat transcript, a file manager that uploads PHP just fine, and a root cron job undone by its own use of a wildcard.

Room: CMess (Gila CMS) Category: Web / Linux Privesc Tools: Gobuster, ffuf

The setup: a Gila CMS install with a support feature that logs more than it should, and a cron job that trusts filenames it shouldn't. The job: find the leaked credentials, get code execution through the admin panel, and abuse the cron job's own tar command to become root.

The Investigation

1
Fuzz for the real subdomain

The base site is mostly static, but subdomain fuzzing against the target's domain turns up a separate host running the actual Gila CMS application.

ffuf -u http://FUZZ.<domain> -H "Host: FUZZ.<domain>" -w /usr/share/wordlists/subdomains.txt
Why this works

Organizations often spin up a CMS or admin panel on a subdomain they don't link to from the main site. DNS/vhost fuzzing finds what a crawler never will.

2
Find leaked credentials in a support chat

The CMS has a live-chat/support widget, and its transcript history is browsable without authentication. Buried in an old conversation, a staff member pastes their own admin username and password while troubleshooting with a colleague.

Why this works

Support and chat logs are a chronically underestimated leak source. People paste credentials into "private" conversations assuming no one else will ever read them, but if the transcript is stored and reachable, it's just another file to find.

3
Upload a webshell through the admin file manager

Logged into the Gila CMS admin panel, the built-in file manager accepts a .php upload with no content-type or extension filtering. Dropping a simple PHP web shell and requesting it directly executes commands on the server.

Why this works

An authenticated file-upload feature in a CMS admin panel is a code-execution primitive by default unless it explicitly restricts extensions and validates content. "Admin can upload files" quietly means "admin can upload a shell" far more often than CMS vendors intend.

4
Spot a cron job archiving a world-writable directory

Enumeration on the box turns up a cron job running as root that periodically runs tar with a wildcard over a directory the low-privilege web user can write to:

tar -czf /backup.tar.gz *
Why this works

Shell wildcard expansion happens before the command runs, and tar treats certain filenames starting with a dash as command-line flags, not filenames. Any writable directory feeding a wildcard into tar (or similar tools) is a known, well-documented privilege-escalation pattern.

5
Exploit the tar wildcard for root

Dropping specially-named files into that writable directory, filenames crafted to be interpreted by tar as its own checkpoint/exec flags, smuggles an arbitrary command into the next cron run, executed as root:

echo 'cp /bin/bash /tmp/rootbash; chmod +s /tmp/rootbash' > shell.sh
touch -- "--checkpoint=1"
touch -- "--checkpoint-action=exec=sh shell.sh"

On the cron's next run, tar parses those filenames as options instead of archive members and executes the script as root, leaving behind a SUID root shell.

Why this works

This is the classic GTFOBins tar wildcard technique: because tar * expands to every filename in the directory, including attacker-chosen ones, and tar's own checkpoint/exec flags can trigger arbitrary commands, a world-writable directory plus a wildcard tar invocation is effectively a root shell waiting to be claimed.

Full Attack Chain

ffuf: hidden Gila CMS subdomain found
  → support chat transcript: admin credentials leaked in plain text
       → admin file manager: PHP webshell uploaded
            → enumeration: root cron job running tar with a wildcard
                 → crafted filenames smuggle a command into tar's own flags
                      → SUID root shell dropped on the next cron run

Takeaways

Support logs are an underrated credential leak source

Any stored transcript, chat log, or ticket history is worth checking for pasted secrets, people treat them as private when they often aren't.

File managers are upload-based RCE unless proven otherwise

An admin panel's file upload feature should always be tested for extension and content-type enforcement, not assumed safe because it's "just for images."

Wildcards in privileged shell commands are dangerous

tar, chown, rsync, and several other common tools interpret certain filenames as flags. A root cron job expanding a wildcard over a writable directory is a well-known, reliable privesc path.
