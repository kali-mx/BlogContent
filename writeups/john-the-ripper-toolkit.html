John the Ripper: a working reference, not just a wordlist run

Most John the Ripper usage stops at a wordlist against a hash file. The more useful half is everything around that: identifying what you're even looking at, pulling hashes out of real-world formats, and writing rules that mangle a wordlist instead of just running it as-is.

Category: Password Cracking Tools: John the Ripper, hashid

Purpose: a consolidated reference for the John the Ripper techniques that come up repeatedly: format identification, Linux credential unshadowing, archive and SSH key cracking, and custom rule-based mangling.

The Reference

1
Identify the hash before guessing a mode

Before cracking anything, confirm what format it actually is:

hashid '<hash string>'
Why this works

John supports dozens of formats, and guessing wrong wastes time running the wrong attack against a hash it will never crack. A ten-second identification step avoids that entirely.

2
Unshadow Linux passwd/shadow pairs

A raw /etc/shadow file isn't directly crackable on its own, it needs merging with /etc/passwd first:

unshadow passwd.txt shadow.txt > combined.txt
john combined.txt --wordlist=/usr/share/wordlists/rockyou.txt
Why this works

shadow holds the hashes, passwd holds the usernames and UIDs that map to them, John needs both joined together in one file to know which hash belongs to which account.

3
Try single-crack mode before a full wordlist

John's single-crack mode generates guesses from the username and any available GECOS field data (full name, etc.) in the password file itself, no external wordlist required:

john --single --format=<format> combined.txt
Why this works

People reuse their own name, username, or small variations of it as passwords constantly. Single-crack mode catches this class of weak password almost instantly, before paying the cost of a full wordlist run.

4
Crack password-protected archives and SSH keys

John's companion scripts convert common container formats into a crackable hash first:

zip2john protected.zip > zip.hash
rar2john protected.rar > rar.hash
ssh2john id_rsa > ssh.hash
john --wordlist=/usr/share/wordlists/rockyou.txt zip.hash
Why this works

A zip, rar, or encrypted SSH private key isn't a "hash" in the usual sense, these helper scripts extract the specific data John needs to brute-force the passphrase protecting the container, in a format John's core engine understands.

5
Write custom mangling rules for a smarter wordlist

Plain wordlists miss predictable variations, a capitalized first letter, a trailing year, a leetspeak substitution. John's rule engine in john.conf generates those variations from a base wordlist without manually writing out every permutation:

[List.Rules:Custom]
c $[0-9] $[0-9]

john --wordlist=base.txt --rules=Custom combined.txt
Why this works

Most real-world weak passwords aren't raw dictionary words, they're a dictionary word plus a predictable tweak. A well-written rule set covers far more realistic password space per wordlist entry than brute-forcing character by character ever could.
