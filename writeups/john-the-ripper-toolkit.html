John the Ripper: a working reference, not just a wordlist run

Most John the Ripper usage stops at a wordlist against a hash file. The more useful half is everything around that: identifying what you're even looking at, pulling hashes out of real-world formats, and writing rules that mangle a wordlist instead of just running it as-is.

Category: Password Cracking Tools: John the Ripper, hashid

Purpose: a consolidated reference for the John the Ripper techniques that come up repeatedly: format identification, Linux credential unshadowing, single-crack mode, archive and SSH key cracking, and custom rule-based mangling.

The Reference

1
Identify the hash before guessing a mode, then crack it

hashid narrows down the hash type before wasting a run on the wrong format:

hashid hash1.txt
--File 'hash1.txt'--
Analyzing '2e728dd31fb5949bc39cac5a9f066498'
[+] MD2

With the format known, John runs against it directly:

john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt hash1.txt
Why this works

John supports dozens of formats, and guessing wrong wastes time running the wrong attack against a hash it will never crack. A ten-second identification step avoids that entirely.

2
Unshadow Linux passwd/shadow pairs

A raw /etc/shadow entry isn't directly crackable on its own, it needs merging with the matching /etc/passwd line first. Built from copied file contents:

echo root:x:0:0::root:/bin/bash > ~/Downloads/lesson/passwd
echo 'root:$6$Ha.d5nGupBm29pYr$yugXSk24ZljLTAZZagtGwpSQhb3F2DOJtnHrvk7HI2ma4GsuioHp8sm3LJiRJpKfIf7lZQ29qgtH17Q/JDpYM/:18576:::::' > shadow

unshadow passwd shadow > unshad

john unshad --wordlist=/usr/share/wordlists/rockyou.txt
Why this works

shadow holds the hash, passwd holds the username and UID it maps to, and John needs both joined into one file to know which hash belongs to which account.

3
Try single-crack mode before a full wordlist

Single-crack mode generates guesses from the username (and any GECOS field data) already present in the file, no external wordlist required. It needs the hash prefixed with its username first:

# from:
1efee03cdcb96d90ad48ccc7b8666033
# to:
mike:1efee03cdcb96d90ad48ccc7b8666033

john --single --format=md5 hash.txt
Why this works

People reuse their own name or username as a password constantly. Single-crack mode catches this class of weak password almost instantly, before paying the cost of a full wordlist run.

4
Crack password-protected zip, rar, and SSH key files

Each container format gets its own converter script that extracts a John-readable hash first:

# zip
zip2john zipfile.zip > zip_hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt zip_hash.txt

# rar
rar2john rarfile.rar > rar_hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt rar_hash.txt

# once cracked, extract with the recovered password:
unrar x -ppassword rar
Extracting from rar
Extracting  flag.txt    OK
All OK

# ssh private key
sudo python /usr/share/john/ssh2john.py id_rsa > idjohn
john --wordlist=/usr/share/wordlists/rockyou.txt idjohn
Why this works

A zip, rar, or encrypted SSH private key isn't a "hash" in the usual sense. These helper scripts extract the specific data John needs to brute-force the passphrase protecting the container, in a format John's core engine understands.

5
Write a custom mangling rule, then crack with it

Plain wordlists miss predictable variations, like a trailing two-digit number. A new rule block added to /etc/john/john.conf:

[List.Rules:THM01]
$[0-9]$[0-9]

Run against a common-password list with that rule applied:

john hash.txt --format=raw-sha1 --wordlist=/usr/share/seclists/Passwords/Common-Credentials/10k-most-common.txt --rules=THM01

1g 0:00:00:00 DONE (2021-07-21 15:41) 25.00g/s 14133Kp/s 14133Kc/s 14133KC/s hotrats56..modena56

john hash.txt --show
?:moonligh56
1 password hash cracked, 0 left

A second rule, built after pulling a list of common first names from GitHub, mangles with trailing digits and punctuation instead:

[List.Rules:THM_Advise1]
c$1$2$3$4$[$%&*-_+=#@~!]
john hash.txt --format=raw-md5 --wordlist=/usr/share/seclists/Usernames/Names/malenames-usa-top1000.txt --rules=THM_Advise1

Zachariah1234*   (?)
1g 0:00:00:00 DONE (2021-07-23 12:00) 100.0g/s 409600p/s 409600c/s 409600C/s Valentin1234*..Chris1234+
Why this works

Most real-world weak passwords aren't raw dictionary words, they're a name or word plus a predictable tweak (a couple of digits, a symbol). A well-written rule set covers far more realistic password space per wordlist entry than brute-forcing character by character ever could, and swapping the base wordlist (a name list instead of a password list) targets a different weak-password habit entirely.
