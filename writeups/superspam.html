SuperSpam: from a leaked WiFi capture to a root VNC password

An anonymous FTP login hands over a wireless packet capture. Cracking it unlocks a CMS admin panel, a CMS admin panel unlocks code execution, and a trail of the attacker's own sloppy encryption leads all the way to a decrypted root VNC password.

Room: SuperSpam Category: Web / Linux Privesc Tools: aircrack-ng, LinPEAS, vncpwd, CyberChef

The setup: a box exposes HTTP, SSH, anonymous FTP, VNC, and X11. Nothing requires exploitation to get started, the anonymous FTP login alone hands over the first real lead.

The flag itself is omitted below, the chain to reach it is the point.

The Investigation

1
Scan, then just log in

A service scan turns up HTTP, a non-standard SSH port, FTP, VNC, and X11:

nmap -sV -sC 10.10.36.244

The FTP server allows anonymous login outright. No credentials needed, just the username anonymous and any password. Inside sits a .cap file and a note.

Why this works

Anonymous FTP is a decades-old misconfiguration that's still worth checking first on any box that has the port open. It costs nothing to try and sometimes, like here, it hands over the entire first stage of the attack.

2
Crack the wireless capture

Opening the .cap file in Wireshark confirms it's an 802.11 wireless capture, which means it might contain a crackable WPA handshake:

aircrack-ng -w /usr/share/wordlists/rockyou.txt SamsNetwork.cap

A dictionary attack against the handshake recovers the network's passphrase in well under ten minutes.

Why this works

A WPA handshake captured off the air is only as strong as the passphrase behind it. Against a dictionary-weak password, cracking it offline is fast, and the password itself often gets reused somewhere else entirely, which is exactly what happens next.

3
Reuse the password against a CMS login

The site on port 80 is running concrete5, with a blog listing posts from four different author accounts. Trying the cracked WiFi passphrase against each of the four usernames in turn finds the one that reuses it, logging straight into the CMS admin dashboard.

Why this works

Password reuse across completely unrelated systems, a home WiFi network and a CMS login, is one of the most reliable pivots in any assessment. Once you have one real password, trying it everywhere costs almost nothing.

4
Turn admin access into code execution

concrete5's System & Settings panel has an Allowed File Types list that, by default, blocks executable uploads. Adding php to that list and saving removes the one thing stopping a webshell upload.

From there, the File Manager accepts a PHP reverse shell (the PentestMonkey shell works fine) and hands back a direct URL to the uploaded file. Visiting that URL with a listener running catches the callback:

nc -lvnp 4444
Why this works

An allowlist is only a control if nothing with admin rights can change it. Any CMS that lets an authenticated admin edit its own upload restrictions is one settings change away from arbitrary file upload, and from there, code execution.

5
Find the attacker's own mistake

Poking around as the web user turns up a directory holding a Python XOR script, a handful of .png images, and a note. The note is the attacker talking to themselves: a reminder not to reuse the same XOR key across multiple encrypted messages, because doing so compromises all of them, and a mention that two specific messages in the set were the most important.

Why this works

XOR encryption is only secure if the key is never reused. Reusing one key across several messages means that once any part of one message is known or guessed, an attacker (or in this case, the actual attacker's own past self) can start recovering the others. The note is effectively a confession of exactly how to break it.

6
Pull the images and recover a password

A quick Python web server on the target plus wget -r pulls the whole directory down for offline analysis:

wget -r 10.10.214.18:8080/

Flipping through the decoded images by hand, one of them is actually readable, and it contains a plaintext password. Trying that password against SSH for each of the four blog usernames from step 3 finds the one it belongs to.

Why this works

Not every piece of leaked data needs to be fully, formally decrypted to be useful, sometimes one readable fragment out of a batch is enough to recover a credential, especially when the attacker's own key-reuse mistake makes some of the set weaker than others.

7
Fix a locked-out home directory

Logging in over SSH with the recovered credential lands a shell, but the user's own home directory is inaccessible, permission denied on their own files. The directory's permissions are simply broken:

chmod -u+x+r+w <username>

Inside, a file named passwd is owned by root and decrypts to nothing readable, pure binary noise when catted to screen.

Why this works

A permission-denied error on your own home directory is a configuration bug worth fixing rather than a wall to work around, the fix here is a one-line chmod. The root-owned file inside it is the next real lead, not a dead end.

8
Identify and decrypt the mystery file

Running LinPEAS turns up the answer: that same byte length and format matches /root/.vnc/passwd, a VNC server's own obfuscated password file, and LinPEAS confirms a copy exists there too. SSH config enumeration adds one more useful detail: root login is permitted on the non-standard SSH port.

VNC passwords aren't hashed, they're encrypted with a fixed, publicly known key, which makes them fully reversible with the right tool:

git clone https://github.com/jeroennijhof/vncpwd
vncpwd passwd
Why this works

VNC's password obfuscation was never designed to resist a targeted attacker, it uses a hardcoded DES key published in the protocol spec decades ago. Any tool built around that key decrypts it instantly, recognizing the file format is the only real work.

9
Connect as root and decode the flag

With the decrypted password, vncviewer connects directly to the root session on port 5901. From there, a flag file in a hidden directory contains two base32-looking strings, the flag itself and a final taunting note from the attacker, both of which decode cleanly by dropping the text into CyberChef's "Magic" recipe and letting it auto-detect the encoding.

Why this works

When a decode chain isn't obvious at a glance, a magic/auto-detect tool like CyberChef's Magic recipe is often faster than guessing encodings by hand, it tries the common transforms and ranks the results by how plausible the output looks.

Full Attack Chain

Anonymous FTP login
  → Wireless capture + note downloaded
       → aircrack-ng: WiFi passphrase cracked
            → Password reused against 4 CMS blog accounts, one matches
                 → concrete5 admin: PHP uploads enabled, webshell uploaded
                      → www-data shell via reverse shell callback
                           → Attacker's own XOR key-reuse note found
                                → Leaked images decoded, a password recovered
                                     → SSH as a real user, home dir permissions fixed
                                          → Root-owned "passwd" file found
                                               → Identified as a VNC password file (LinPEAS)
                                                    → vncpwd decrypts it
                                                         → vncviewer: root session
                                                              → Flag decoded via CyberChef Magic

Takeaways

Anonymous access is still worth trying first

An FTP server that allows anonymous login handed over the entire first stage of this chain. Checking for it costs nothing and should happen before anything more involved.

Password reuse collapses unrelated systems together

A WiFi passphrase and a CMS login had nothing to do with each other technically, except that the same human reused the same password for both.

XOR key reuse is a self-inflicted wound

The attacker's own note described the exact mistake that made their encrypted messages crackable. Reusing a stream cipher key is one of the most well-known, most consequential cryptography errors there is.

Legacy protocols can still have reversible "encryption"

VNC's password obfuscation uses a fixed, publicly documented key. Any file in that format should be treated as effectively plaintext to anyone who finds it.
