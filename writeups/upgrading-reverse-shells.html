Upgrading a Netcat Shell to a Full TTY

A raw netcat reverse shell can't handle Ctrl-C, tab completion, or most interactive tools like a real terminal can. A few lines turn it into one.

Category: Post-Exploitation Tools: netcat, python, stty

Purpose: a working sequence for upgrading a bare netcat shell into a fully interactive TTY, including the fixes needed when terminal detection doesn't go smoothly.

The Reference

1
Spawn a real pty on the target

If Python is available on the target, this is the first step:

python -c 'import pty;pty.spawn("/bin/bash")'
Why this works

A raw netcat connection is just a pipe, it has no concept of a terminal. pty.spawn allocates an actual pseudo-terminal on the target end, which is the prerequisite for everything else here.

2
Background the session and fix local terminal state

Suspend the netcat session with Ctrl-Z, then on the attacker side:

stty raw -echo; fg
reset
Why this works

stty raw -echo stops the local terminal from double-handling input (echoing and line-buffering) now that the remote pty is handling it instead. Backgrounding and foregrounding (fg) with that setting applied is what makes the shell start behaving like a real session, Ctrl-C included.

3
Match the terminal size

Check the local terminal's current dimensions, then set the same values on the remote shell:

stty -a
stty rows <rows> columns <columns>
Why this works

Without matching dimensions, full-screen tools (editors, pagers, anything using ncurses) render incorrectly or wrap text unpredictably. This is a cosmetic step, but it's the difference between a usable shell and a frustrating one.

4
Recover when the upgrade doesn't go cleanly

Sometimes reset prompts for a terminal type it doesn't recognize. Answering with xterm-256color, or falling back to plain xterm if that's rejected too, usually resolves it. If the shell still isn't behaving, setting the environment directly helps:

export TERM=xterm
export SHELL=bash
Why this works

A shell spawned through a reverse connection doesn't always inherit the environment variables a normal login session would. Setting TERM and SHELL explicitly fills in what a proper login would have set automatically.
